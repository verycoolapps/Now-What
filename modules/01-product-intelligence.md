# MODULE 01 — PRODUCT INTELLIGENCE SCAN
## Deep-Dive Product Analysis Framework

> **Purpose:** Before making a single commercial recommendation, we must fully understand what the product IS, what it DOES, and whether it is READY. Misidentifying a product's category or readiness level leads to catastrophically wrong strategies.

---

## 1.1 PRODUCT IDENTITY INTERROGATION

Run these questions against every product you receive. Do not skip items — an unanswered question is a business risk.

```
CORE IDENTITY
├── Product Name (official and working title)
├── Product Category (see 1.2)
├── Product Type (B2B / B2C / B2G / Dual-sided)
├── Primary Function (what does it do in one sentence?)
├── Mechanism (how does it work?)
├── Technology Stack (what is it built with?)
├── Problem Solved (specific, not vague)
├── Unique Attributes (what makes it different?)
├── Maturity Level (prototype / beta / v1 / mature)
└── Commercial Readiness (can it be sold today?)
```

---

## 1.2 PRODUCT CLASSIFICATION ENGINE

Identifying the product type is CRITICAL — different types demand completely different commercialization paths.

| Product Type | Key Characteristics | Primary Monetization | Typical Channels |
|-------------|-------------------|---------------------|-----------------|
| **Physical Product** | Tangible, manufactured, inventory | Unit sale, wholesale | Retail, e-commerce, distribution |
| **Digital Product** | Downloadable, no inventory | One-time sale, license | Digital marketplaces, website |
| **Software (Desktop)** | Installable application | License, subscription | Direct, AppSumo, Gumroad |
| **SaaS** | Cloud-hosted, always-on | Subscription (MRR/ARR) | Product-led, sales-led |
| **Mobile Application** | iOS/Android, app store | Freemium, IAP, subscription | App Store, Google Play |
| **Web Application** | Browser-based tool | Subscription, freemium | SEO, SEM, Product Hunt |
| **AI Product** | ML-powered intelligence | API calls, subscription | Developer channels, enterprise |
| **Game** | Entertainment, interactive | Premium, F2P, DLC | Steam, Epic, mobile stores |
| **Hardware** | Physical + digital | Unit sale, platform | Direct, distributors, B2B |
| **Creative Product** | Design, media, content | License, one-time | Envato, Creative Market, Etsy |
| **Educational Product** | Learning, training | Course fee, subscription | Udemy, direct, B2B |
| **Business Solution** | Enterprise workflow | License, subscription, implementation | Direct sales, partners |
| **Professional Service** | Human-delivered expertise | Retainer, project fee | Network, LinkedIn, referral |

**Classification Rule:** If a product spans multiple types, identify the PRIMARY type first, then secondary. Commercialization strategy follows the primary type.

## 1.3 PRODUCT READINESS ASSESSMENT SYSTEM

Score each dimension from 0–100. Provide evidence for each score. Mark unavailable data as UNKNOWN.

### Scoring Rubric

| Score Range | Meaning |
|------------|---------|
| 0–20 | Critical gaps — not ready |
| 21–40 | Major gaps — requires significant work |
| 41–60 | Partial readiness — gaps acceptable for limited launch |
| 61–80 | Strong readiness — ready for initial market |
| 81–100 | Excellent — ready for scale |

### Readiness Dimensions

**PRODUCT FUNCTIONALITY (0–100)**
Does the core function work reliably?
- 0: Product does not function
- 50: Core function works, secondary features incomplete
- 100: All functions work flawlessly under real conditions

**PRODUCT QUALITY (0–100)**
Does quality meet the minimum bar for the target market?
- Consider: bug rate, performance, error handling, stability under load
- Do not set quality standard to perfection — set it to "would a paying customer tolerate this?"

**USER EXPERIENCE (0–100)**
Can a target user operate the product without hand-holding?
- 0: Requires expert guidance to use
- 50: Usable with documentation
- 100: Intuitive — zero learning curve for target user

**RELIABILITY (0–100)**
Does the product perform consistently?
- For software: uptime, error rates, data integrity
- For physical: durability, failure rates, consistency

**MARKET READINESS (0–100)**
Is there evidence that a real market needs this?
- 0: No validation at all
- 50: Some customer interviews, unproven demand
- 100: Signed LOIs, waitlist, paying beta customers

**COMMERCIAL READINESS (0–100)**
Are the commercial infrastructure components in place?
- Pricing defined? Payment processing? Sales materials? Legal agreements? Customer support?

**COMPETITIVE ADVANTAGE (0–100)**
Does the product have a defensible differentiation?
- 0: Identical to existing solutions
- 50: Marginally better in one dimension
- 100: Unique capability that competitors cannot easily replicate

**SCALABILITY (0–100)**
Can the product serve 10x customers without breaking?
- For software: architecture, infrastructure, team
- For physical: manufacturing, supply chain, fulfillment
- For services: delivery model, documentation, delegation

**LEGAL READINESS (0–100)**
Are legal and compliance requirements addressed?
- IP protection, business registration, required certifications, data privacy compliance

**CUSTOMER SUPPORT (0–100)**
Is there a system to handle customer issues?
- 0: No plan
- 50: Founder handles all support manually
- 100: Documented process, dedicated support, SLAs defined

## 1.4 READINESS VERDICT FRAMEWORK

After scoring all dimensions:

**TOTAL SCORE INTERPRETATION**

| Total Score (avg) | Verdict | Action |
|------------------|---------|--------|
| 0–30 | NOT READY | Do not sell. Fix critical gaps first. |
| 31–50 | CONDITIONALLY READY | Sell to 1–3 pilot customers only. Fix gaps with real feedback. |
| 51–70 | LAUNCH READY | Begin controlled commercial launch. Monitor closely. |
| 71–85 | STRONG LAUNCH | Execute full go-to-market. Prioritize growth. |
| 86–100 | SCALE READY | Aggressive commercialization. Expand markets and channels. |

**CRITICAL FLAGS (automatic blockers regardless of total score):**
- Functionality < 50 → Do not sell
- Legal Readiness < 30 → Consult legal counsel before any commercial activity
- Reliability < 40 for SaaS/software → Fix before selling

## 1.5 PRODUCT STORY MAPPING

After assessment, construct the product's commercial narrative:

```
PRODUCT STORY TEMPLATE
"[Product Name] is a [type] that helps [target customer]
solve [specific problem] by [mechanism],
delivering [measurable outcome],
unlike [current alternative] which [key limitation]."
```

This story becomes the foundation for all positioning, messaging, and sales materials.
